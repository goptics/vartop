# vartop web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `vartop web` serves a local htmx dashboard (trends, pod grid, worker detail, controls) for the active varmq server.

**Architecture:** A per-server `Session` owns an `api.Pool`, one poller goroutine and an in-memory ring of immutable snapshots; a `Manager` swaps sessions on server switch. HTTP handlers only read snapshots, build view models (`view.go`) and render `html/template` pages; the browser polls the same URL and swaps `#live` via `hx-select`. Mutations fan out to pods through ctx-aware `api.Client` methods.

**Tech Stack:** Go 1.26 stdlib (`net/http`, `html/template`, `embed`, `sync/atomic`), existing `internal/api`, `internal/config`, cobra; vendored htmx 2.0.4 (static file, not a Go module).

**Spec:** `docs/superpowers/specs/2026-10-25-web-ui-design.md`

## Global Constraints

- No new Go module dependencies. No Node/npm. No JS chart library; charts are inline SVG `<polyline>` built server-side.
- htmx pinned: `https://unpkg.com/htmx.org@2.0.4/dist/htmx.min.js`, vendored as `internal/web/static/htmx-2.0.4.min.js`, served via `go:embed`.
- TUI behaviour unchanged; existing `api.Client` methods keep their signatures and behaviour.
- Bind loopback only; default `--addr 127.0.0.1:7070`.
- Token never appears in any HTML/HTTP response.
- Before modifying an existing symbol run GitNexus `impact({target, direction: "upstream", repo: "vartop"})` and report risk; before each commit run `detect_changes({scope: "staged", repo: "vartop"})`. Re-index first if stale: `node .gitnexus/run.cjs analyze` (or `npx gitnexus analyze`).
- Every commit: `gofmt -l .` empty, `go vet ./...` clean, `go test -race ./...` green. Conventional commit subjects; body ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never stage `AGENTS.md`, `CLAUDE.md`, `.claude/`.
- Exact UI copy (verbatim from spec):
  - Pending column/card label: `Pending (max/pod)`
  - Rates on load-balanced endpoints: `n/a: load-balanced`
  - Stale tab banner: `Server changed to {name} — reload`
  - Startup: `Connecting to {label}…`
  - Missing worker badge: `absent on {k} pods`
  - varmq 409 result: `no change ({msg})`
  - Concurrency cell: `{n} ×{p} pods` (all equal, p>1), `{n}` (one pod), `mixed {min}–{max}`
  - Health: `●` all healthy, `◐` some, `○` none, followed by `{healthy}/{total} pods`
  - LB warning: `⚠️  Load-balanced endpoint: {host} ({n} instances seen), …. Each refresh shows one instance; use kubernetes or dns discovery to see all.` (hosts sorted, joined by `, `; mirror `internal/tui/dashboard.go:339-352`)
- Status classes: `Idle`, `Running` → `active`; `Initiated`, `Pausing`, `Stopping` → `transitional`; `Paused` → `paused`; `Stopped` → `stopped`; anything else → `unknown`. Colours: active = success green, paused = warning yellow, stopped = error red, others = plain fg (Tokyo Night hexes from `internal/tui/styles.go:9-18`).
- Success rate = successful / (successful + failed) × 100, shown `—` when the denominator is 0 (TUI `internal/tui/detail.go:331-336`).
- Trend windows: row and KPI sparklines = last 10 minutes; detail chart = whole history (≤ 1 hour).

## Review Focus

1. Worker names with `/`, spaces or unicode: must reach varmq path-escaped, render escaped, and get a safe stable DOM id. (Task 4 poller test, Task 8 action test, Task 3 `ID` test.)
2. Empty states: zero pods (k8s with no ready endpoints), zero workers, first snapshot (no rates yet): pages render, no panic, no divide-by-zero in sparkline scaling. (Task 3, Task 6 tests.)
3. Slow pod at a short interval: one pod slower than the tick deadline must be marked errored while other pods still report; ticks must not stack. (Task 4 test.)
4. Worker removed between `GET /workers` and `GET /workers/{name}` (404): skip the worker, don't mark the pod errored. (Task 4 test.)
5. `--addr` port already in use: clear error naming the address, not a panic or a silent second instance. (Task 7 test.)

```go
type Sample struct {
	At            time.Time // when this worker's GetWorker response arrived
	api.WorkerDetails         // includes Instance
	CompletedRate float64   // per second; valid only if RateOK
	FailedRate    float64
	RateOK        bool
}
type PodSnapshot struct {
	Endpoint     string             // pod key (Client.PrimaryEndpoint())
	Label        string             // display label captured at poll time
	Err          string             // "" = healthy
	LoadBalanced int                // instances seen behind this endpoint (>1 = LB)
	Workers      map[string]*Sample // by worker name
}
type Snapshot struct {
	At   time.Time
	Pods []PodSnapshot // sorted by Endpoint
}
func NewHistory(interval time.Duration) *History        // capacity = ceil(time.Hour / interval)
func (h *History) Append(s *Snapshot)                     // fills rates, then publishes; s is immutable afterwards
func (h *History) Snapshots() []*Snapshot                  // oldest → newest, copy of pointers
func (h *History) Latest() *Snapshot                       // nil when empty
func (h *History) Interval() time.Duration
func rate(prev, cur *Sample, interval time.Duration) (completed, failed float64, ok bool)
```

Rate rules (spec "Poller and history" 4): `ok=false` when `prev == nil`; `cur.Metrics.Completed < prev.Metrics.Completed` or same for `Failed`; `cur.Instance != prev.Instance`; `Δt < interval/2`; `Δt > 3*interval`. Otherwise `Δcounter / Δt.Seconds()`. `Append` looks up `prev` from an internal `last map[endpoint+"\x00"+worker]*Sample` (updated on every append; `ponytail:` never pruned, entries for vanished pods are tiny and fall out of the 3× window). Ring guarded by `sync.RWMutex`.
