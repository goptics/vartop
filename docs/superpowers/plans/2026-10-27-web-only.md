# vartop web-only (no daemon, no TUI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** vartop becomes CLI + `vartop web`. `vartop web` collects every configured server into the SQLite store while it runs and stops collecting when it exits; the detached daemon, its login service and the TUI are gone.

**Architecture:** `vartop web` runs the collector (today's `daemon.Run`, renamed `collect.Run`) in-process, in a loop tied to the web's context. The store, its lease (now the one-writer guard), pokes and the 24h history stay as built. Everything that only existed to run, find, start, stop, supervise or display from a separate process goes.

**Tech Stack:** Go 1.26, cobra, htmx 2.0.4, modernc.org/sqlite (kept).

**Spec:** `docs/superpowers/specs/2026-10-26-collector-daemon-design.md` (R1–R45) plus the owner's decisions below; Task 5 records them there as R46.

## Owner's decisions (2026-10-27)

| Topic | Decision |
|---|---|
| Daemon | Removed: no `vartop daemon …`, no login service, no detached process |
| TUI | Removed: `vartop` with no subcommand prints help |
| Collection | Starts when `vartop web` starts, stops when it exits; polls every configured server |
| History | SQLite store, 24h retention, as today; survives a restart of `vartop web` |
| Two `vartop web` on one data dir | One collects (holds the lease); the other serves what it collects and takes over when it stops |
| Flags | `vartop web --host 127.0.0.1 --port 7070` replace `--addr`; host stays loopback-only (no auth on the dashboard) |
| CLI | `server …`, `workers …` unchanged (they never used the store) |

## Global Constraints

- `--host` default `127.0.0.1`, `--port` default `7070`; a non-loopback host is refused by `web.Listen` as today.
- Data dir, file names, schema and `StoreVersion` unchanged: an existing `~/.cache/vartop` keeps working, its history included. The `daemon.stop` column stays in the schema, unused (no migration).
- Tokens are never written to the store.
- Never stage `AGENTS.md`, `CLAUDE.md`, `.claude/`, `LICENSE`.
- GitNexus: refresh the index first (`npx -y gitnexus@latest analyze --index-only`), `impact` before editing a symbol, `detect-changes` before each commit. Renames of symbols go through GitNexus `rename`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Each task leaves `go vet ./...`, `gofmt -l .` (empty) and `go test -race ./...` green.

## Review Focus

1. Ctrl+C on `vartop web` while a poll hangs → it exits within `shutdownTimeout` + one poll deadline, releases the lease, and no goroutine keeps polling.
2. Two `vartop web` on one data dir → exactly one writer; stopping it, the other takes over within `store.DeadAfter` + one retry, and its pages go current again without a reload.
3. A second `vartop web` with another config (`VARTOP_CONFIG`/`KUBECONFIG`) while the first collects → pages show the other-configuration notice, actions refused (R44 still holds).
4. `vartop web` started on a data dir an old `vartop daemon` (previous build) still holds → it waits for that lease like a second web; the notice says another process collects, with its pid.
5. The data dir deleted while `vartop web` runs → the collector loop logs, re-opens a fresh store and continues; the web does not exit.

### Task 2: Collect in-process from `vartop web`

**Files:**
- Move: `internal/daemon/` → `internal/collect/` (package `collect`; the unexported `daemon` type → `run`; `Run`, `Options` keep their names)
- Modify: `cmd/web.go` (start/stop the collector), `cmd/web_test.go`
- Modify: `cmd/daemon.go` only to point at the moved package (deleted in Task 3)

**Interfaces:**
- Produces: `func collectLoop(ctx context.Context, o collect.Options, retry time.Duration, log *slog.Logger)` in `cmd/web.go`: calls `collect.Run(ctx, o)` until `ctx` ends; after a return with code 0 it calls again at once (Run already waited `store.DeadAfter` on a fresh foreign lease); after an error it logs and waits `retry` (5s). Logs once per change: "collecting", "another vartop (pid N) is collecting into <dir>; showing what it collects", errors.
- `webCmd.RunE` starts `collectLoop` in a goroutine before `serveWeb`, and after `serveWeb` returns waits for it (it ends with ctx and releases the lease). `startCollecting` is no longer called.
- Lease: `store.Lease{PID, ConfigPath, Kubeconfig, Started}` built in `cmd/web.go` (today's `ownLease` minus build identity).

- [ ] **Tests** (over `fleettest` fakes, temp `VARTOP_DATA_DIR`, temp config):

  - `TestSecondWebDoesNotCollect`: a fresh lease held by another token that keeps beating → `collectLoop` never claims; once that lease is released, it claims within `store.DeadAfter + 1s`.
  - `TestCollectLoopRetriesAfterError`: `collect.Run` failing (data dir unwritable, then fixed) → logged once, collects after the fix.
